`lmsysorg/sglang:nightly-dev-cu13-20260909-db272201` (torch 2.13.0+cu130), with each
PR branch on `PYTHONPATH` so the image's own sglang is shadowed by the branch source.

100 (`layers/quantization/fp8.py:302`) and H200 is 90. So this closes the "unit tests
were not run locally" gap in all three PR bodies, and validates #38609 end to end on a
model that H200 *can* load; the HYV4 e2e evidence stays the B300 run.

## The #38609 matrix

`TABLE.md` is generated by `make_table.py` from `results/*.json` — never transcribed.
Three axes, all stamped into every filename: whether the model class carries
`get_model_config_for_expert_location`, whether the metadata is read before or after
the `ep_dispatch_algorithm is None` early return, and whether an EPLB dispatch
algorithm is configured. `remove_hook.py` deletes the classmethod to reproduce the
state HYV4 is in; `run_arm.sh` runs one server per row and `probe.py` takes greedy
completions over 5 fixed prompts, whose SHA-256 is the "completions" column.

Two things the matrix settled that the source reading alone did not:

* the crash needs an **a2a backend**. `init_new` is only called from the
  `_forward_deepep` paths, so with `--moe-a2a-backend none` a hookless class serves
  fine on `main` today. The over-broad claim in the PR body was corrected in a comment.
* nothing else moves. All five served rows produced byte-identical completions,
  including both `--ep-dispatch-algorithm static` rows, so the configured path is
  untouched by the reorder.
